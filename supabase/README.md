# Wortel on Supabase

Backend for the Wortel word-guessing game: Supabase Edge Functions + Postgres + Auth.

## Stack

- **Postgres** — `public.games` (game state, JSONB attempts, optimistic locking) and
  `public.daily_challenges`, both with Row Level Security
- **Auth** — Supabase Auth (Google OAuth, anonymous sign-in); JWTs verified inside the
  Edge Function with `auth.getClaims()` (local JWKS check for asymmetric keys)
- **Edge Function** `games` — Deno 2 / TypeScript REST API
- **Word lists** — 4–7 letters, bundled as TS modules in
  `functions/_shared/infrastructure/data/` (generated by `wordlists/wordlist_creator.py`)

### Architecture rules

| Layer | May import |
| --- | --- |
| `domain/` | `domain/` only — pure TS, no `Deno`, no external modules |
| `ports/` | `domain/`, `ports/` |
| `application/` | `domain/`, `ports/`, `application/` — no `Deno`, no external modules |
| `infrastructure/` | `domain/`, `ports/` + Supabase/Deno |
| `http/` | `domain/`, `ports/`, `application/` — knows `Request`/`Response`, never infrastructure |
| `games/index.ts` | everything — it wires concrete adapters into use cases |

`_shared/architecture.test.ts` checks these rules on every `deno task test`, so a
violation fails CI. Business rules (word lengths, attempt limits, daily rules, hint
selection) belong in `domain/`; repositories only persist.

Migrating away from Supabase = new implementations of the ports in `infrastructure/`
plus new wiring in `games/index.ts`. Domain and application stay untouched.

## API (Edge Function `games`)

Base URL: `https://<project-ref>.supabase.co/functions/v1/games` · full spec in
[`docs/openapi.yaml`](../docs/openapi.yaml)

| Method | Path | Body | Description |
| --- | --- | --- | --- |
| POST | `/games` | `{ "wordLength"?: 4..7, "maxAttempts"?: 1..20 }` | Create game (201) |
| GET | `/games/{id}` | — | Game state |
| POST | `/games/{id}/guesses` | `{ "guess": "haben" }` | Submit a guess |
| POST | `/games/{id}/hint` | — | Hint word that reveals a new correct letter |
| GET | `/games/daily` | — | Today's challenge metadata (never the secret) |
| POST | `/games/daily` | — | Play today's daily (idempotent) |

**Auth:** `Authorization: Bearer <supabase-jwt>` binds the game to the user. Without a
valid JWT (no header, the publishable key, an expired token) the game is anonymous and
anyone with its id can access it. Anonymous daily play needs `X-Anonymous-Id: <uuid>`
(stable per install).

**Responses:** unknown words and wrong lengths are normal gameplay — `200` with the
unchanged state plus `rejectedGuess`. Errors are `{ "error", "code" }`:
`400` invalid input · `403` not the owner · `404` unknown game · `409` game finished or
concurrent update · `422` no hint available · `500` `INTERNAL` (details only in logs).

## Development

```bash
cd supabase/functions
deno task verify      # fmt:check + check + lint + test (what CI runs)
deno task fmt         # format
```

Local stack (Docker + Supabase CLI 3):

```bash
supabase start                   # Postgres, Auth, REST, Edge runtime; applies migrations
supabase db reset                # drop + re-apply all migrations
supabase functions serve games   # http://127.0.0.1:54321/functions/v1/games

curl -X POST http://127.0.0.1:54321/functions/v1/games \
  -H "Authorization: Bearer <PUBLISHABLE_KEY from supabase status>" \
  -H 'Content-Type: application/json' \
  -d '{"wordLength":5,"maxAttempts":6}'
```

`SUPABASE_URL` and the API keys are injected automatically. Optional
`supabase/.env.local` (gitignored) for `WORTEL_CORS_ALLOWED_ORIGINS`.

## Deploy

deploy` → smoke test. Details and secrets: [`docs/DEPLOYMENT.md`](../docs/DEPLOYMENT.md).

## Database notes

- The Edge Function uses the secret (service-role) key and enforces ownership in
  `Game.canBeAccessedBy`; RLS additionally limits direct PostgREST access to a user's
  own games.
- `daily_challenges` is not readable through PostgREST at all (`using (false)`), since
  RLS cannot hide the `secret_word` column.
- One daily entry per user is enforced by unique indexes on `(user_id, daily_day)` and
  `(anonymous_id, daily_day)`.
